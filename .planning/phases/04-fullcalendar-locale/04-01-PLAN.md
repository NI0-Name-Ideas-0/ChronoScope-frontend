# Plan 04-01: Wire FullCalendar locale to LanguageService

## Objective

Make FullCalendar respond to the app's active language so that all calendar UI elements (button labels, day/month names, week text) render in the correct locale — English or German — and update reactively when the user switches language.

## Context

- FullCalendar v6.1.20 is already installed with `@fullcalendar/core`, `@fullcalendar/angular`, `@fullcalendar/daygrid`, `@fullcalendar/timegrid`, `@fullcalendar/rrule`
- The calendar component is at `src/app/components/calendar-view/calendar/calendar.ts`
- It currently has `locale: 'en-GB'` hardcoded in `calendarOptions`
- `LanguageService` (from Phase 3) exposes a `language` signal (`'en' | 'de'`)
- FullCalendar supports multiple locales via `locales` array + `setOption('locale', ...)` for runtime switching
- German locale available at `@fullcalendar/core/locales/de`
- Known FullCalendar bug (#4591): some locales have inconsistent buttonText mapping — workaround is to explicitly set `buttonText` per locale
- Only buttons to translate: `today`, `month`, `week` (per header toolbar: `timeGridWeek dayGridMonth` and `today prev,next`)

## Tasks

### Task 1: Import DE locale and configure calendarOptions

**File:** `src/app/components/calendar-view/calendar/calendar.ts`

1. Import the German locale object:
   ```typescript
   import deLocale from '@fullcalendar/core/locales/de';
   ```
2. Import `LanguageService` and `AppLocale`:
   ```typescript
   import { LanguageService, AppLocale } from '@services/language.service';
   ```
3. Add `locales: [deLocale]` to `calendarOptions` so FullCalendar knows about the DE locale
4. Remove the hardcoded `locale: 'en-GB'` — the locale will be set dynamically

### Task 2: Add buttonText workaround map

**File:** `src/app/components/calendar-view/calendar/calendar.ts`

Create a static map of button text overrides for each supported locale to work around FullCalendar bug #4591:

```typescript
private static readonly BUTTON_TEXT: Record<AppLocale, { today: string; month: string; week: string }> = {
  en: { today: 'today', month: 'month', week: 'week' },
  de: { today: 'Heute', month: 'Monat', week: 'Woche' },
};
```

### Task 3: Create reactive locale effect

**File:** `src/app/components/calendar-view/calendar/calendar.ts`

1. Inject `LanguageService` into the component
2. Create an `effect()` that watches `languageService.language()` and calls:
   - `api.setOption('locale', lang)` to switch FullCalendar's locale
   - `api.setOption('buttonText', Calendar.BUTTON_TEXT[lang])` as the bug workaround
3. Ensure the effect only runs after `calendarRef` is available (guard with `if (this.calendarRef)`)
4. Set initial locale in `calendarOptions` from `languageService.language()` (for first render before the effect fires)

### Task 4: Update translation files

**Files:** `public/i18n/en.json`, `public/i18n/de.json`

No new Transloco keys needed — FullCalendar handles its own button text translations via its locale system. Skip this task.

### Task 5: Verify and test

1. Run `pnpm build` to confirm no compilation errors
2. Run `pnpm test` to confirm all existing tests still pass
3. If the calendar spec exists, ensure it still works with the LanguageService injection
