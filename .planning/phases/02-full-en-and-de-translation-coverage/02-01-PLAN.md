- src/app/components/navbar/navbar.html (verify key usage context for navigation)

<action>
Open public/i18n/en.json and review every key-value pair. For each area, verify:

NAVIGATION (keys starting with NAV_): Values should be concise navigation labels — "Dashboard", "Calendar", "Tasks", etc.

SETTINGS (keys starting with SETTINGS_): Values should be clear section titles and labels. Verify appearance, account-security, organizations, and work-preferences sections have natural headings.

TASKS (keys starting with TASK_): Values should be natural action labels — "Create Task", "Edit Task", "Due Date", "Priority", etc. Check calendar-view and list-view keys too.

FORMS/VALIDATION (keys containing VALIDATION_, FORM_, or ending in _PLACEHOLDER, _LABEL, _ERROR): Verify messages like "This field is required", "Title cannot be empty" read naturally.

NOTIFICATIONS/TOASTS (keys starting with TOAST_ or NOTIFICATION_): Verify messages like "Task created", "Task updated", "Unable to reach the server" are concise and clear.

Correct any values that:
- Are overly verbose for their context (e.g., button labels should be 1-3 words)
- Don't match the UI context where they appear
- Have inconsistent capitalization (use Title Case for headings, Sentence case for descriptions)
- Contain placeholder text like "TODO" or "FIXME"

Per D-01 context: English should match the friendly, direct tone of modern SaaS apps like Notion and Linear.
</action>

- Navigation keys (NAV_*) have concise 1-3 word labels

<task id="02-01-2">
<objective>Review and correct de.json — ensure all German translations use informal "du" tone and read naturally</objective>
<read_first>
- public/i18n/de.json (current state of all German translations from Phase 1)
- public/i18n/en.json (reference for meaning — ensure DE matches EN intent)
- src/app/components/settings-modal/sections/appearance/appearance.html (verify appearance context)
- src/app/components/list-view/list-view.html (verify list-view context)
</read_first>
<action>
Open public/i18n/de.json and review every key-value pair. Apply these corrections per D-01 (informal "du" tone):

TONE RULES (per D-01 — NON-NEGOTIABLE):
- Always "du/dein/dir" — NEVER "Sie/Ihr/Ihnen"
- "Dein Profil" not "Ihr Profil"
- "Erstelle eine Aufgabe" not "Erstellen Sie eine Aufgabe"
- "Speichere" or "Speichern" (imperative informal) not "Speichern Sie"
- Possessives: "dein/deine/deinen" not "Ihr/Ihre/Ihren"

NATURAL GERMAN (not literal translations):
- "Dashboard" stays "Dashboard" (common in German tech)
- "Settings" → "Einstellungen" (not "Konfiguration")
- "Save" → "Speichern"
- "Cancel" → "Abbrechen"
- "Delete" → "Löschen"
- "Create Task" → "Aufgabe erstellen"
- "Due Date" → "Fälligkeitsdatum"
- "Priority" → "Priorität"
- "This field is required" → "Dieses Feld ist erforderlich"
- "Task created" → "Aufgabe erstellt"
- "Task updated" → "Aufgabe aktualisiert"
- "Task deleted" → "Aufgabe gelöscht"
- "Unable to reach the server" → "Server nicht erreichbar. Bitte überprüfe deine Verbindung."
- "Work schedule saved" → "Arbeitszeiten gespeichert"
- "Appearance" → "Darstellung"
- "Account & Security" → "Konto & Sicherheit"
- "Organizations" → "Organisationen"
- "Work Preferences" → "Arbeitszeiten"

For every key, verify the German is:
1. Using informal "du" (search for and replace any "Sie"/"Ihr"/"Ihnen" forms)
2. Contextually natural (not word-for-word)
3. Consistent in terminology across related keys
4. Using correct German grammar (cases, articles, compound nouns)

Ensure both files have EXACTLY the same set of keys (same count, same key names). If en.json has a key that de.json lacks (or vice versa), add the missing translation.
</action>
<acceptance_criteria>
- public/i18n/de.json contains zero instances of formal "Sie", "Ihr ", "Ihnen", "Ihre " addressing (verified via: grep -i "\"Sie \|\"Ihr \|\"Ihnen\|\"Ihre " public/i18n/de.json returns no results)
- de.json has exactly the same number of keys as en.json (verified via comparing key counts with jq or node script)
- Every key in de.json has a non-empty string value
- German text uses informal possessives: any "dein/deine/deinem/deinen/deiner" present instead of "Ihr" forms
- No English text remains in de.json values (except for universally used English terms like "Dashboard", "E-Mail", "App")
</acceptance_criteria>
