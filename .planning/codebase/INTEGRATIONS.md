INTEGRATIONS

**Analysis Date:** 2026-05-16

Summary

This application integrates with an OpenAPI backend (chronoscope API), an OpenID Connect identity provider (auth.ni0.team), FullCalendar (with rrule), Tailwind/DaisyUI for styling, and GitHub Actions for CI/CD. The codebase uses an ng-openapi-gen generated API client and angular-oauth2-oidc for authentication.

APIs & External Services

- Backend API: ChronoScope API
  - Purpose: Primary REST backend for tasks, planning, identity and account linking.
  - How integrated: Typed client generated by `ng-openapi-gen` (generated files under `src/api/`). App uses `src/api/api.ts` and `src/api/api-configuration.ts` via the `Api` service.
  - Configuration location: `src/environments/environment.ts` and `src/environments/environment.prod.ts` expose `apiUrl`. The API root URL is provided to the application in `src/app/app.config.ts` via `provideApiConfiguration(environment.apiUrl)`.
  - Key code locations: `src/api/` (generated client), `src/services/task.service.ts` (calls `api.invoke(...)`), `src/services/auth.ts` (invokes `getIdentity`), `src/app/app.config.ts` (provider registration).

- Authentication / Identity Provider: auth.ni0.team (OpenID Connect)
  - Purpose: User authentication, authorization, token management (OIDC).
  - How integrated: `angular-oauth2-oidc` library used to configure OIDC client and automatic token refresh. The OAuth client is provided in `src/app/app.config.ts` via `provideOAuthClient(...)` and configured programmatically in `src/services/auth.ts`.
  - Configuration details (non-secret): issuer and endpoints configured in `src/services/auth.ts`:
    - `issuer`: `https://auth.ni0.team/realms/ni0`
    - `loginUrl`, `tokenEndpoint`, `userinfoEndpoint` are set to the auth host under `/protocol/openid-connect/...` (see `src/services/auth.ts`).
  - Token usage: HTTP interceptor `src/app/interceptors/oauth.interceptor.ts` attaches `Authorization: Bearer <token>` to requests made to allowed API URLs (`https://chronoscope.ni0.team`, `http://localhost:8080`).
  - Key code locations: `src/services/auth.ts`, `src/app/app.config.ts`, `src/app/interceptors/oauth.interceptor.ts`.

- OpenAPI / Generated client
  - Purpose: Provides a typed, centralized client for backend endpoints, created by `ng-openapi-gen`.
  - How integrated: Generated artifacts live in `src/api/` and are consumed via the injectable `Api` service `src/api/api.ts`.
  - Key files: `src/api/api.ts`, `src/api/api-configuration.ts`, `src/api/functions.ts`, `src/api/models.ts`.

UI & Libraries (third-party SDKs)

- FullCalendar (+ rrule plugin)
  - Purpose: Calendar UI rendering and recurrence rules support.
  - How integrated: `@fullcalendar/angular` and related plugins are imported in `src/app/components/calendar-view/calendar/calendar.ts` (see `imports` and `plugins` array). The application uses `rrule` parsing in `src/services/task.service.ts`.
  - Key files: `src/app/components/calendar-view/calendar/calendar.ts`, `src/services/task.service.ts`.

- rrule (recurrence rules)
  - Purpose: Parse and validate recurrence rules (RFC 5545) for repeating tasks.
  - How integrated: `rrule` package in `package.json` and used in `src/services/task.service.ts` and calendar event generation.

- TailwindCSS & DaisyUI
  - Purpose: Styling, themes and component utilities.
  - How integrated: Tailwind and DaisyUI are referenced in `package.json` and the project applies themes/plugins in `src/styles.css` (DaisyUI theme definitions and `@plugin` references). Build integration is through PostCSS/Tailwind (devDependencies include `tailwindcss` and `@tailwindcss/postcss`).
  - Key files: `src/styles.css`, `package.json` (devDependencies).

CI/CD & Deployment

- GitHub Actions
  - Purpose: Run tests and (on main branch) deploy builds to a remote host.
  - How integrated: Workflow defined in `.github/workflows/ci.yml`.
  - Key steps: installs pnpm, uses Node 22, runs `pnpm install` and `pnpm test`. Deploy job uses `appleboy/ssh-action` with GitHub secrets.
  - Secrets referenced (do not store values in repo): `HOST_IP`, `SSH_USER`, `DEPLOY_KEY`, `SSH_PASSPHRASE`.
