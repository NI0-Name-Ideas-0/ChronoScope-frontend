## Directory purposes and how to use them

- `src/app/`:
  - Purpose: Main UI layer. Contains the root component, routes, and feature components.
  - Contains: Standalone components (`@Component` with `imports`), templates (`*.html`), styles (`*.css`), modal components, and small domain models.
  - Key files: `src/app/app.ts`, `src/app/app.config.ts`, `src/app/app.routes.ts`, `src/app/components/*`.

- `src/services/`:
  - Purpose: Cross-component services and singletons for auth, API orchestration, theme, modals and other application concerns.
  - Contains: Injectable classes (`@Injectable({ providedIn: 'root' })`).
  - Key files: `src/services/auth.ts`, `src/services/task.service.ts`, `src/services/view.service.ts`.

- `src/api/`:
  - Purpose: Generated API client (models, functions, configuration). All network calls are routed through `src/api/api.ts` and the generated function wrappers.
  - Editing guidance: This folder is generated by `ng-openapi-gen`; prefer updating the OpenAPI spec and re-generating rather than editing files by hand.

- `src/environments/`:
  - Purpose: Environment-specific runtime configuration. Swapped during production build (see `angular.json` fileReplacements).
  - Key file: `src/environments/environment.ts` (dev API base URL: `http://localhost:8080`).

- `public/`:
  - Purpose: Static assets (icons, manifest) that are copied into the build output. Entries are configured under the `assets` option in `angular.json`.

## Key file responsibilities (quick map)
- `src/index.html` — Browser entry HTML and host element (`<app-root>`).
- `src/main.ts` — Calls `bootstrapApplication(App, appConfig)` to start the SPA.
- `src/app/app.ts` — Root component; initializes theme and triggers auth login flow.
- `src/app/app.config.ts` — Application-wide providers: router, HTTP client with interceptors, OAuth client, API configuration.
- `src/app/app.routes.ts` — Route table (component-based routes).
- `src/services/task.service.ts` — Responsible for loading tasks, converting API responses to `Task` model instances, caching and exposing `tasks$` observable. Also calls `plan` API when necessary.
- `src/services/auth.ts` — Configures OAuth client, manages identity load and `authReady$` observable.
- `src/api/api.ts` — Low-level wrapper used by service layer to call generated functions and map responses.

## Naming and placement guidance (where to add new code)
- New UI component or feature view:
  - Place component files in `src/app/components/<feature>/` and follow existing pattern: `<feature>.ts`, `<feature>.html`, `<feature>.css`.
  - Use standalone components (add `standalone: true` where appropriate) and import dependencies via the `imports` array inside `@Component`.

- New cross-component service:
  - Add under `src/services/` and mark `@Injectable({ providedIn: 'root' })` to make it globally available.

- API changes:
  - Update OpenAPI specification and re-run `ng-openapi-gen` to regenerate `src/api/*` (do not manually edit generated files).

- Utilities and pipes:
  - Place shared pipes in `src/pipes/` and shared small pure helpers under `src/app/` or `src/services/` depending on scope.

## Tests and specs
- Unit tests co-exist as `.spec.ts` files next to their modules (e.g. `src/app/*/*.spec.ts`, `src/services/*.spec.ts`). Test runner in `package.json` is `ng test`.

## Special notes
- Path aliases are configured in `tsconfig.json` (e.g. `@app/*` -> `src/app/*`, `@services/*` -> `src/services/*`) — use them when importing across the codebase.
- App uses Angular 21 and the modern standalone API surface; prefer signals and OnPush CD for new components to match project style.
- The `src/api/` folder is generated; treat it as an API boundary layer and do not scatter raw HTTP calls across components — use `src/services/*` to orchestrate network operations.
