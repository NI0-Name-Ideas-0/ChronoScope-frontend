## Known Gaps & Observations
1. Coverage reporting is not configured and no thresholds enforced. This means regressions can slip through without coverage visibility.
2. No E2E test suite for user flows, routing, or authentication flows. Critical user journeys (login flow, calendar interactions) lack end-to-end verification.
3. No centralized test setup/teardown file or testing utilities. Each spec repeats TestBed setup and inline mocks.
4. No documented test running commands beyond `ng test` in `package.json` scripts (no `test:ci`, `test:coverage`, or `vitest` scripts).
5. No mocking/factory utilities or fixtures for common domain objects (e.g., tasks, events, organizations generated by the API client) — many tests create inline mocks.
6. No test for generated API client (`src/api`) or integration tests that exercise API invocation stubs.

## Recommendations & Quick Prioritized Next Steps
1. Add coverage collection and thresholds (High priority)
   - Add a `vitest.config.ts` or configure Angular unit-test builder to enable coverage collection. Example script additions in `package.json`:
     - `"test:coverage": "pnpm test -- --coverage --watch=false"` or configure `vitest --coverage` directly if switching to explicit Vitest runner.
   - Add coverage threshold enforcement in CI and fail the job if thresholds drop below configured values.
   - Save coverage artifacts in CI and optionally upload to a coverage service.
   - Files to add: `vitest.config.ts` (root), `package.json` scripts.

2. Introduce a global test setup and shared test utilities (Medium priority)
   - Add `test/setup.ts` to register common mocks, polyfills (jsdom configs), and providers used across tests.
   - Export a `test/mock-factories.ts` for domain fixtures to avoid repeated inline mocks.
   - Update `tsconfig.spec.json` `include` if necessary to include the setup file.

3. Add E2E testing (Medium priority)
   - Start with Playwright or Cypress to cover critical user journeys (login, calendar create/edit, account linking). Prefer Playwright for modern tooling and test reliability.
   - Place E2E tests under `e2e/` or `tests/e2e/` and add CI job that runs against a built preview.

4. Add targeted integration tests for API clients (Low/Medium priority)
   - Tests for `src/api/*` generated client that stub network responses (msw or mocked `fetch`/`HttpClient`) to verify request shapes.

5. Add test-related scripts to `package.json` (Low priority, quick wins)
   - `"test:ci": "pnpm test -- --watch=false"`
   - `"test:watch": "pnpm test"`
   - `"vitest": "vitest"` and `"vitest:coverage": "vitest --coverage"` if adopting vitest runner directly.

6. Add accessibility testing to test pipeline (Medium priority)
   - Integrate axe checks in unit tests for critical components and in E2E for pages.
   - Add `@axe-core/playwright` or `axe-core` + `jest-axe` equivalent for Vitest.

7. Centralize mocking utilities and adopt `vi.spyOn` and `vi.mock` patterns where appropriate to standardize mocking.
