# ARCHITECTURE

**Analysis Date:** 2026-05-16

## High-level overview
ChronoScope is a single-page Angular 21 application focused on task scheduling, planning and lightweight calendar/list views. Major subsystems:
- UI (standalone components and templates): `src/app/components/*`
- Application bootstrap and routing: `src/main.ts`, `src/app/app.config.ts`, `src/app/app.routes.ts`
- Feature components and views: `src/app/components/*`
- Client-side state & services (signals and RxJS subjects): `src/services/*`
- API surface & generated client: `src/api/*` (generated by `ng-openapi-gen`)
- Authentication / OAuth2: `src/services/auth.ts` + `angular-oauth2-oidc`
- HTTP interceptors: `src/app/interceptors/*`

## Entry points (index.html, main.ts, bootstrap flow)
- HTML entry: `src/index.html` — contains `<app-root></app-root>` and static metadata/assets.
- Angular bootstrap: `src/main.ts` calls `bootstrapApplication(App, appConfig)`.
  - `App` component: `src/app/app.ts` (standalone root component)
  - `appConfig`: `src/app/app.config.ts` — central ApplicationConfig where providers are registered (router, HTTP client, api configuration, OAuth client, global error listeners, interceptors).
- Route registration happens via `provideRouter(routes)` where `routes` are imported from `src/app/app.routes.ts`.
- The build entry used by Angular CLI is `browser: "src/main.ts"` (see `angular.json`).

## Routing and lazy-loading
- Routes live in `src/app/app.routes.ts`. Current route configuration is small and component-based:
  - `path: 'link-account'` -> `LinkAccount` component (`src/app/components/link-account/link-account.ts`)
  - fallback `path: '**'` -> `Main` component (`src/app/components/main/main.ts`)
- The codebase favors standalone components and direct component imports in routes; there is no explicit feature-module lazy-loading configuration detected (no `loadChildren` entries in `src/app/app.routes.ts`).
- Because components are standalone and imported directly, enabling route-level lazy-loading would require converting components to NgModules or using dynamic import statements in routes (not present currently).

## Component layering: key components, shared vs feature, services
- Root/Host:
  - `src/app/app.ts` (root standalone component)
  - `src/app/app.html` template contains `<router-outlet />`.
- Top-level feature container:
  - `src/app/components/main/main.ts` hosts primary views: `CalendarView`, `ListView`, `Navbar`, `Topbar`.
- Feature components (examples):
  - `src/app/components/calendar-view/*`
  - `src/app/components/list-view/*`
  - `src/app/components/navbar/*`
  - `src/app/components/topbar/*`
  - Modals: `src/app/components/settings-modal/*`, `task-modal/*`
- Shared services (application-scoped singletons): providedIn root
  - `src/services/task.service.ts` — primary task store and API orchestrator (uses `BehaviorSubject` for tasks$)
  - `src/services/view.service.ts` — view-local state using Angular `signal` primitives
  - `src/services/auth.ts` — OAuth configuration, identity loading and auth state (`BehaviorSubject`)
  - `src/services/theme.service.ts`, `task-modal.service.ts`, `work-slot-preference.service.ts`, etc.
- UI/presentation is implemented with OnPush change detection and signals where appropriate to minimize change detection surface (`ChangeDetectionStrategy.OnPush` used in many components).

## State management
- Two complementary approaches are used:
  1. Angular signals for component/view-local reactive state (examples: `signal(...)` used in `src/app/app.ts`, `src/services/view.service.ts`, `src/app/components/*` files).
  2. Services with RxJS subjects/BehaviorSubject for cross-component shared state and async data streams (example: `src/services/task.service.ts` exposes `tasks$` as an Observable backed by `BehaviorSubject`).
- Persistent small pieces of UI state are stored in `localStorage` by `TaskService` (completion state saved under the key `'chronoscope-completion'`).
- Authentication state is exposed via `Auth.identity$` (BehaviorSubject/Observable).

## Dataflow / API interaction
- The code uses a generated OpenAPI client under `src/api/` (generated by `ng-openapi-gen`). Core files:
  - `src/api/api.ts` - Api helper service that wraps `HttpClient` and standardizes invocation
  - `src/api/api-configuration.ts` - `ApiConfiguration` provider; `appConfig` sets `provideApiConfiguration(environment.apiUrl)` to configure runtime root URL
  - `src/api/functions.ts`, `src/api/models.ts` - generated function wrappers and models
- HTTP interception for attaching access tokens is implemented in `src/app/interceptors/oauth.interceptor.ts` and wired into the app via `provideHttpClient(withInterceptors([oauthInterceptor]))` in `src/app/app.config.ts`.
- Typical flow for fetching tasks:
  1. On auth ready (`Auth.authReady$`), `TaskService.loadTasks()` invokes `api.invoke(getTasksApi, params)` (`src/services/task.service.ts` -> `src/api/functions.ts`).
  2. The raw response may be a Blob (API client returns StrictHttpResponse); TaskService parses blobs and converts to local model classes (`src/app/model/*`).
  3. TaskService updates its `tasks` Map and emits via `tasksSubject` (observable `tasks$`) which UI components subscribe to.
- Client side planning endpoint is called via `planApi` from `TaskService` when tasks change and planning is required.

## Build/runtime considerations and platform-specific notes
- Angular version: ^21.x (see `package.json`) — using standalone component APIs and `bootstrapApplication` style.
- TypeScript target is ES2022 (see `tsconfig.json`), baseUrl is `src`, and path aliases are configured (e.g. `@app/*`, `@services/*`, `@api/*`).
- Build config (`angular.json`):
  - Builder: `@angular/build:application` (CLI alias for Angular build)
  - Entry (browser): `src/main.ts`
  - Assets: `public` is copied into the build output (see `angular.json` assets setting)
  - `outputMode: "static"` set in `angular.json` build options
  - Production configuration replaces `src/environments/environment.ts` with `src/environments/environment.prod.ts` (file replacement)
- Authentication relies on `angular-oauth2-oidc` and an external identity provider configured in `src/services/auth.ts` (issuer `https://auth.ni0.team/realms/ni0`). This affects runtime (CORS, redirect URIs, cookie policies).
- API root URL is injected at bootstrap using `provideApiConfiguration(environment.apiUrl)` (see `src/environments/environment.ts` and `src/app/app.config.ts`). `environment.apiUrl` defaults to `http://localhost:8080` for dev.

## Diagrams / ASCII sketch
Primary runtime layers and flow:

  Browser / DOM
    └─ `src/index.html` -> `src/main.ts` (bootstrapApplication)
         └─ `App` (`src/app/app.ts`) [router outlet]
              ├─ Router -> `Main` (`src/app/components/main/main.ts`) or `LinkAccount`
              ├─ Components -> `src/app/components/*`
              └─ Services injected (Auth, TaskService, ViewService, ThemeService)
                 └─ `Api` (`src/api/api.ts`) -> HTTP -> backend (`environment.apiUrl`)

Data flow (tasks):
  Backend API (GET /tasks) -> `Api.invoke` (`src/api/api.ts`) -> `TaskService.loadTasks()` -> `tasks$` BehaviorSubject -> UI subscribers (`ListView`, `Topbar`, `Calendar`)
