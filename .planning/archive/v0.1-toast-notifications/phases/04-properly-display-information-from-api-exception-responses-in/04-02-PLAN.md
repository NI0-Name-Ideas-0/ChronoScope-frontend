  <action>
    Add the following test cases to `error.interceptor.spec.ts` within the existing `describe('errorInterceptor')` block. Import `ChronoscopeError` from `@app/model/chronoscope-error.model`.

    Test: "should use errorCode-mapped title when ProblemDetail has errorCode in properties"
    - Flush a response body with `{ detail: 'No available time slots', title: 'Planning Failed', status: 409, type: 'urn:chronoscope:error:insufficient-slots', properties: { errorCode: 'INSUFFICIENT_SLOTS' } }` and HTTP status 409.
    - Assert `notifications()[0].title` equals `'Planning Failed'` (from ERROR_CODE_TITLES map).
    - Assert `notifications()[0].message` equals `'No available time slots'`.

    Test: "should fall back to ProblemDetail title when errorCode is unknown"
    - Flush a response body with `{ detail: 'Something weird', title: 'Custom Error', status: 400, properties: { errorCode: 'UNKNOWN_CODE' } }` and HTTP status 400.
    - Assert `notifications()[0].title` equals `'Custom Error'` (fallback to body.title).

    Test: "should parse fieldErrors from ProblemDetail properties and include in notification"
    - Flush a response body with `{ detail: 'Request validation failed', title: 'Validation Failed', status: 400, type: 'urn:chronoscope:error:validation-error', properties: { errorCode: 'VALIDATION_ERROR', fieldErrors: [{ field: 'name', message: 'must not be blank' }, { field: 'dueDate', message: 'must be in the future' }] } }` and HTTP status 400.
    - Assert `notifications()[0].fieldErrors` has length 2.
    - Assert `notifications()[0].fieldErrors![0].field` equals `'name'` and `.message` equals `'must not be blank'`.
    - Assert `notifications()[0].fieldErrors![1].field` equals `'dueDate'`.

    Test: "should re-throw ChronoscopeError with errorCode and typeUri for programmatic handling"
    - Flush a response body with `{ detail: 'Task not found', title: 'Not Found', status: 404, type: 'urn:chronoscope:error:resource-not-found', properties: { errorCode: 'RESOURCE_NOT_FOUND' } }` and HTTP status 404.
    - In the subscribe `error` callback, capture the error.
    - Assert the caught error `instanceof ChronoscopeError`.
    - Assert `caughtError.errorCode` equals `'RESOURCE_NOT_FOUND'`.
    - Assert `caughtError.typeUri` equals `'urn:chronoscope:error:resource-not-found'`.
    - Assert `caughtError.status` equals `404`.
    - Assert `caughtError.detail` equals `'Task not found'`.

    Test: "should still re-throw ChronoscopeError when SKIP_ERROR_TOAST is set"
    - Use `SKIP_ERROR_TOAST` context with `true`, flush a ProblemDetail with errorCode.
    - Assert no notifications are created (length 0).
    - Assert the caught error `instanceof ChronoscopeError` with the correct `errorCode`.

    Test: "should not include fieldErrors in notification when ProblemDetail has no fieldErrors"
    - Flush a response body with errorCode but no fieldErrors property.
    - Assert `notifications()[0].fieldErrors` is `undefined` or not present.
  </action>
